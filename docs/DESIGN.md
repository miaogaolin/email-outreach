# Email Outreach 设计说明

## 目标

在 Obsidian 内完成「筛选客户 → 勾选客户 → 生成开发邮件 → 人工审核 → 写回 Markdown」，AI 规则由用户的知识库决定，插件只固定输出结构与安全边界。插件不发送邮件。

## 模块地图

| 模块 | 职责 |
|---|---|
| `core/contact-parser.ts` | 解析 `## Contact` / `## 联系人`；两种写法：列表项姓名 + 缩进子项，纯姓名行 + 顶级列表；姓名行支持 `姓名(身份) 备注`（中英文括号、姓名与括号间可有空格，括号后的文字记为备注）；按邮箱/原文定位联系人 |
| `core/ai-file.ts` | AI 开发信息文件的渲染与解析（往返一致）；邮件块、版本历史；多封邮件批量追加、ID 连续 |
| `core/schema.ts` | AI JSON 校验：联系人 id、邮箱比对、逐封邮件校验、摘要、语言；部分成功保留有效邮件 |
| `core/prompt.ts` | 固定 system 契约 + 业务知识注入 + 邮件/规则两类 user prompt |
| `core/send-time.ts` | 客户地区 → IANA 时区；按跟进次数、最近联系、已发送记录计算发送时间，多封错峰 |
| `core/follow-up.ts` | 跟进次数解析与「标记已发送」+1 |
| `core/run-status.ts` | 上次执行状态：标签、提醒汇总、`.state/last-run.json` 解析 |
| `core/filters.ts` | 内置工作台的属性筛选、排除规则、类型推断 |
| `core/language.ts` | 国家/地区 → 语言 + 默认 IANA 时区；未知地区返回 null 触发人工确认 |
| `obsidian/pipeline.ts` | 批量编排：并发、重试、取消、失败隔离、多封邮件即时落盘 |
| `obsidian/bases-view.ts` | 自定义 Bases 视图：复用 Base 的筛选/列/排序，加固定「开发状态」列与单一生成按钮 |
| `obsidian/email-store.ts` | 扫描输出目录，聚合所有 AI 文件中的邮件行 |
| `obsidian/main.ts` | 生命周期、命令、视图注册、审核动作、上次执行状态、规则沉淀 |

## 关键决策

1. **一个客户一个 AI 文件**：`{客户名} - AI开发信息.md`。全部邮件、版本历史都在这里；一个客户可以为多位适合联系人各生成一封，最多 5 封，不会产生副本文件。
2. **客户定位只用双链**：`customer: "[[...]]"`，不存路径；客户改名由 Obsidian 维护链接，失效时按 basename 兜底。
3. **收件人来自本地解析**：AI 选 `contact_id`，插件从本地联系人取邮箱，AI 给的邮箱只用于比对，防止幻觉地址。
4. **只为适合的联系人写信**：AI 返回 `emails[]`，空数组表示没有合适联系人并附带原因；本地没有带邮箱联系人时直接跳过，不调用 AI。
5. **部分成功**：逐封校验，非法邮件丢弃并告警；至少一封有效即可落盘，全部非法才触发修复重试。
6. **发送时间由程序计算**：客户当地时间工作日 09:30；首次联系下一个工作日，第 1/2/3+ 次跟进间隔 3/5/7 个工作日；同客户多封按工作日错峰。理由里带北京时间对照。
7. **写回范围最小**：验收只写一个 `AI开发信息` 双链；只有「标记已发送」改 `跟进次数` 和 `最近联系时间`。旧分析区段保留，但新版本不再写分析字段。
8. **Bases 优先，内置兜底**：Bases 1.10+ 提供 `registerBasesView`；不注册 `options`，只依赖 `data/config/onDataUpdated`。运行结束后主动刷新活动 Bases 视图。
9. **构建不依赖子进程**：沙箱禁止 spawn，`scripts/build.mjs` 用 TypeScript API 编译 + 自定义 CJS 注册表输出单文件 `main.js`。

## 数据流

```
Bases/内置工作台 ──勾选──▶ runTasks（单一「生成开发邮件」动作）
   │
   │ 知识库加载：主指令 + [[双链]] 文章（深度/字数上限）
   │ 确认弹窗（客户数、生成规则）
   ▼
Pipeline（并发 1–5）
   ├─ 解析联系人（本地）
   ├─ 没有带邮箱联系人 → 状态 no_contact，不调用 AI
   ├─ 邮件请求 → 校验 → 逐封计算发送时间 → 批量写入 AI 文件（状态 Generated）
   ├─ AI 返回 emails: [] → 状态 no_suitable，不写文件
   └─ 失败：原始响应写 {输出目录}/.state/
   ▼
{输出目录}/.state/last-run.json（每客户开发状态）
   ▼
客户工作台「开发状态」列 + 邮件列表顶部提醒
   ▼
邮件列表（悬停预览 / 详情）→ 编辑/重生成（追加版本）→ 验收/拒绝
   ▼
验收通过：状态 Accepted + 客户属性写一个双链
   ▼
标记已发送：sent=true + 跟进次数+1 + 最近联系时间=当天
   ▼
保存为长期规则 → Feedback.md → 下次生成自动参考
```

## 文件格式不变式

- 邮件块标题：`### 邮件 NNN · 联系人 · 状态`。
- 元数据：`- key: value`，单行；中文摘要、发送时间、时区、时间理由都在这里。
- `#### Subject` / `#### Body` / `#### 修改历史`。
- 版本围栏：反引号数量 = 内容中最长反引号串 + 1（最少 4），避免正文含 ``` 时错位。
- 顶层 YAML：`type`、`customer`、`updated`、`email_count`、`last_status`；不写 `customer_path`。
- 多封邮件追加在同一个 `## 邮件` 区段，ID 按现有最大值连续递增。

## 安全边界

- 未配置完整不执行；确认弹窗之前不发起任何请求。
- AI 输出必须过校验；全部非法才重试一次，仍失败只报错不落盘。
- 已有 AI 文件无法解析时不覆盖、不追加，原始内容保留。
- 客户原始文件只改 `AI开发信息`、`跟进次数`、`最近联系时间`。
- 不发送邮件、不抓网站、不自动加跟进次数。

## 验证方式

- `npm.cmd run typecheck`、`npm.cmd run test`、`npm.cmd run build`、`node scripts/smoke-load.cjs`。
- 真实客户库抽样：`node scripts/dev-parse-report.mjs "<客户目录>"`。
- Obsidian 内手动验收：启用插件 → 配置 → Bases 视图勾选客户 → 生成 → 审核 → 详情编辑 → 验收 → 标记已发送。
