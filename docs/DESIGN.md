# Email Outreach 设计说明

## 目标

在 Obsidian 内完成「筛选客户 → 勾选客户 → 生成开发邮件 → 人工审核 → 写回 Markdown」，AI 规则由用户的知识库决定，插件只固定输出结构与安全边界。插件不发送邮件。

## 模块地图

| 模块 | 职责 |
|---|---|
| `core/contact-parser.ts` | 解析 `## Contact` / `## 联系人`；两种写法：列表项姓名 + 缩进子项，纯姓名行 + 顶级列表；姓名行支持 `姓名(身份) 备注`（中英文括号、姓名与括号间可有空格，括号后的文字记为备注）；按邮箱/原文定位联系人 |
| `core/ai-file.ts` | AI 开发信息文件的渲染与解析（往返一致）；邮件块、版本历史；多封邮件批量追加、ID 连续 |
| `core/schema.ts` | AI JSON 校验：联系人 id、邮箱比对、逐封邮件校验、摘要、语言；部分成功保留有效邮件 |
| `core/prompt.ts` | 固定 system 契约 + 业务知识注入 + 邮件/规则两类 user prompt |
| `core/send-time.ts` | 客户地区 → IANA 时区；按跟进次数、最近联系、已发送记录计算发送时间，多封错峰 |
| `core/follow-up.ts` | 跟进次数解析与「标记已发送」+1 |
| `core/run-status.ts` | 上次执行状态：标签、提醒汇总、`.state/last-run.json` 与 `.state/customer-status.json` 解析、按客户合并 |
| `core/generation.ts` | 从 AI 开发信息文件的 `generated_at` 只读推导「最近生成时间」；待审计数；生成时间筛选与冷却判断；客户 ↔ AI 文件匹配 |
| `core/dev-state.ts` | 合并「最近生成」与「上次尝试」成一列 `CustomerDevView`（主行时间 / 副行未解决提醒 / tooltip） |
| `core/email-list.ts` | 邮件列表的客户筛选与「同邮箱待审去重」；先判定去重再做状态/搜索过滤 |
| `core/filters.ts` | 内置工作台的属性筛选、排除规则、类型推断；`FilterRuntime` 追加生成时间筛选 |
| `core/language.ts` | 国家/地区 → 语言 + 默认 IANA 时区；未知地区返回 null 触发人工确认 |
| `obsidian/pipeline.ts` | 批量编排：并发、重试、取消、失败隔离、多封邮件即时落盘 |
| `obsidian/bases-view.ts` | 自定义 Bases 视图：复用 Base 的筛选/列/排序，加合并「开发状态」列、生成时间筛选与单一生成按钮 |
| `obsidian/dev-status-cell.ts` | 两个工作台共用的「开发状态」单元格：两行渲染 + `✉` 角标 + 跳转到该客户的邮件列表 |
| `obsidian/email-store.ts` | 扫描输出目录，聚合所有 AI 文件中的邮件行；`listFiles()` 供生成索引只读使用 |
| `obsidian/main.ts` | 生命周期、命令、视图注册、审核动作、上次执行与每客户状态、冷却守卫、规则沉淀 |

## 关键决策

1. **一个客户一个 AI 文件**：`{客户名} - AI开发信息.md`。全部邮件、版本历史都在这里；一个客户可以为多位适合联系人各生成一封，最多 5 封，不会产生副本文件。
2. **客户定位只用双链**：`customer: "[[...]]"`，不存路径；客户改名由 Obsidian 维护链接，失效时按 basename 兜底。
3. **收件人来自本地解析**：AI 选 `contact_id`，插件从本地联系人取邮箱，AI 给的邮箱只用于比对，防止幻觉地址。
4. **只为适合的联系人写信**：AI 返回 `emails[]`，空数组表示没有合适联系人并附带原因；本地没有带邮箱联系人时直接跳过，不调用 AI。
5. **部分成功**：逐封校验，非法邮件丢弃并告警；至少一封有效即可落盘，全部非法才触发修复重试。
6. **发送时间由程序计算**：客户当地时间工作日 09:30；首次联系下一个工作日，第 1/2/3+ 次跟进间隔 3/5/7 个工作日；同客户多封按工作日错峰。理由里带北京时间对照。
7. **写回范围最小**：验收只写一个 `AI开发信息` 双链；只有「标记已发送」改 `跟进次数` 和 `最近联系时间`。旧分析区段保留，但新版本不再写分析字段。
8. **最近生成时间只读推导**：唯一真源是 AI 开发信息文件里每封邮件的 `generated_at`（老文件回退到第一个版本时间），客户笔记零写入。已拒绝的邮件不算「已生成」，允许当天重做；AI 文件存在但解析不出邮件块时为「未知」，不参与「未生成」筛选。
9. **「开发状态」一列两行**：主行是最近生成时间，副行只显示尚未解决的上次尝试提醒（之后有更晚的成功生成就隐藏）。每客户的上次尝试存 `.state/customer-status.json` 并跨批次合并；`last-run.json` 只留给顶部横幅。AI 文件缺失但上次记录说「已生成」时，副行提示文件缺失，冷却仍用该时间兜底。
10. **冷却守卫在入口**：`runTasks` 先按最新 AI 文件建索引，把勾选客户分成「冷却中 / 可生成」，默认跳过冷却中的客户，另给「仍然全部生成」；`0` 关闭。放在入口而不是 Pipeline，能同时覆盖两个工作台和命令调用。
11. **同邮箱待审只显示最新**：以「客户 + 邮箱」分组（默认按 AI 文件路径，避免跳到 A 客户时被 B 客户的更新邮件挤掉），组内按 `updated_at` 取最新；最新一封已验收时旧待审也隐藏，已拒绝不抑制。只影响显示，不删除不修改文件。
12. **Bases 优先，内置兜底**：Bases 1.10+ 提供 `registerBasesView`；不注册 `options`，只依赖 `data/config/onDataUpdated`。运行结束后主动刷新活动 Bases 视图。派生字段（最近生成）由插件视图级筛选提供，Base 原生筛选看不到。
13. **构建不依赖子进程**：沙箱禁止 spawn，`scripts/build.mjs` 用 TypeScript API 编译 + 自定义 CJS 注册表输出单文件 `main.js`。

## 数据流

```
Bases/内置工作台 ──勾选──▶ runTasks（单一「生成开发邮件」动作）
   │
   │ 生成索引（AI 文件 generated_at，全量客户）→ 冷却守卫（默认跳过 24h 内已生成的客户）
   │ 知识库加载：主指令 + [[双链]] 文章（深度/字数上限）
   │ 确认弹窗（客户数、生成规则、被跳过的客户）
   ▼
Pipeline（并发 1–5）
   ├─ 解析联系人（本地）
   ├─ 没有带邮箱联系人 → 状态 no_contact，不调用 AI
   ├─ 邮件请求 → 校验 → 逐封计算发送时间 → 批量写入 AI 文件（状态 Generated）
   ├─ AI 返回 emails: [] → 状态 no_suitable，不写文件
   └─ 失败：原始响应写 {输出目录}/.state/
   ▼
{输出目录}/.state/last-run.json（本次执行） + .state/customer-status.json（按客户合并）
   ▼
客户工作台「开发状态」列（主行最近生成 + 副行未解决提醒） + 邮件列表顶部提醒
   ▼
邮件列表（悬停预览 / 详情）→ 编辑/重生成（追加版本）→ 验收/拒绝
   │  同客户同邮箱的待审只显示最新一封（可展开）
   ▼
验收通过：状态 Accepted + 客户属性写一个双链
   ▼
标记已发送：sent=true + 跟进次数+1 + 最近联系时间=当天
   ▼
保存为长期规则 → Feedback.md → 下次生成自动参考
```

## 「最近生成」数据口径

- 有效邮件：`status !== "Rejected"` 且能解析出生成时间（`generated_at`，老文件回退到 `versions[0].at`）。
- 客户最近生成 = 该客户名下所有有效邮件的最大生成时间；AI 文件存在但解析不出邮件块 → 「未知」；没有对应 AI 文件 → 「从未」；全部邮件被拒绝 → 「已拒绝」。
- 客户 ↔ AI 文件匹配优先级：`customer` 双链带目录时与客户路径完全一致 → 客户属性 `AI开发信息` 双链反查（改名后仍有效）→ 唯一 basename。出现同名歧义时按「未知」处理，孤立 AI 文件在视图底部提示，不硬猜归属。
- 筛选与冷却都按绝对时间差（N × 24 小时）计算，不用自然日；未来时间（系统时间被调早）按 0 处理，冷却不阻塞。
- 同邮箱待审的「最新」= `email_updated_at` 最大；时间相同按邮件 ID 数字大者，再按文件路径稳定排序。

## 文件格式不变式

- 邮件块标题：`### 邮件 NNN · 联系人 · 状态`。
- 元数据：`- key: value`，单行；中文摘要、发送时间、时区、时间理由都在这里。
- `#### Subject` / `#### Body` / `#### 修改历史`。
- 版本围栏：反引号数量 = 内容中最长反引号串 + 1（最少 4），避免正文含 ``` 时错位。
- 顶层 YAML：`type`、`customer`、`updated`、`email_count`、`last_status`；不写 `customer_path`。
- 多封邮件追加在同一个 `## 邮件` 区段，ID 按现有最大值连续递增。

## 安全边界

- 未配置完整不执行；确认弹窗之前不发起任何请求。
- AI 输出必须过校验；全部非法才重试一次，仍失败只报错不落盘。
- 已有 AI 文件无法解析时不覆盖、不追加，原始内容保留。
- 客户原始文件只改 `AI开发信息`、`跟进次数`、`最近联系时间`。
- 不发送邮件、不抓网站、不自动加跟进次数。

## 验证方式

- `npm.cmd run typecheck`、`npm.cmd run test`、`npm.cmd run build`、`node scripts/smoke-load.cjs`。
- 真实客户库抽样：`node scripts/dev-parse-report.mjs "<客户目录>"`。
- Obsidian 内手动验收：启用插件 → 配置 → Bases 视图勾选客户 → 生成 → 审核 → 详情编辑 → 验收 → 标记已发送。
